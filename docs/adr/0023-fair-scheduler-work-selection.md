# ADR 0023: fair scheduler work selection

Date: 8 September 2026. Status: implemented; all three focused owner regressions and the full 196-check repository verification passed; deployed performance qualification pending.

The subscription runtime passed real crash, overflow, mandatory-return and causal-trace checks, but `load-diagnostic-1788898990473` still missed the dispatch target: 63.667% of 600 measured movements within two seconds, original-eligibility p99 11,631.762 ms and task-created-stage p99 10,972 ms. All 650 total effects completed once and every application database recorded zero deadlocks. For the representative slow outbound movement, assignment followed original eligibility by about one second; the subsequent dispatch wait accounted for most of its 13-second delay. The transport change is therefore not presented as complete performance remediation.

The owner workers selected the oldest sixteen nonterminal tasks before asking the adapter which already had recorded commands. Repeated observation of sixteen older commands could fill every polling batch while new eligible work remained outside the candidate window. Blocked or retrying tasks could have the same effect. Changing an original eligibility timestamp would conceal this waiting time and is not a remedy.

Each owner now selects two disjoint groups under the same sixteen-task bound. Up to twelve places go to `READY`/`PLANNED` tasks without a recorded dispatch-acceptance timestamp. The remaining places go to retries and observation, ordered by their next-attempt time so an old item that was just checked does not monopolize that group. At least four places remain available to that second group when fresh work is saturated; unused fresh capacity is available to it as well. Work on transport pause, cancellation hold, an unexpired lease or an explicit reconciliation hold retains the existing exclusions.

Fulfilment's fresh group keeps priority/eligibility ordering; returns keeps receipt FIFO ordering. The original SQL and Java scheduling proposals still rank the supplied bounded snapshot, and all route, epoch, lane, physical-evidence and lease checks still apply. The selector changes which waiting work receives a turn. It grants no new dispatch authority. The three coordinators implement the selection in their own databases; no shared business task type is introduced.

`recordedCommandsCannotStarveANewEligibleMovement` uses four actual owner databases to record sixteen commands without advancing equipment, then submits a new eligible movement. The previous selector fails to dispatch that movement. The corrected selector dispatches it and also advances observation of older commands, with zero invented physical or inventory completions. The old implementation failed at 22:33:56 Europe/Berlin and the correction passed at 22:37:16. Equivalent legacy and returns regressions check their separate ownership paths.

The tradeoff is a bounded share of each polling turn between new work and rechecks. Fresh-only turns may use twelve of sixteen places. Original eligibility and durable journal timestamps remain the measurement inputs; no latency exclusion, workload reduction, durability relaxation or artificial stock replenishment is used. Full owner verification passed all 196 checks. Subsequent bounded diagnostics reached 91.167% and 100% within two seconds respectively; both are retained and neither qualifies A50. [ADR 0024](0024-independent-adapter-periodic-work.md) addresses a separate scheduling dependency before renewed sustained measurement.
