# ADR 0015: Observe actual PostgreSQL filesystem headroom

Status: accepted; component and deployed evidence are recorded separately.

Logical database and retained-message quotas cannot establish the free space on the filesystem backing PostgreSQL. Add a small, credential-free probe beside each PostgreSQL instance. It measures that mounted filesystem with `df` every two seconds and atomically replaces one bounded JSON observation on a separate shared report mount. Its database-data mount is read-only. The application-cluster probe shares its existing database pod's network restrictions; the independent simulator probe has no network.

The local PostgreSQL administrator installs `cutover_ops.volume_status()` separately from business migrations. The function reads only the fixed report path, at most 4,097 bytes, and rejects malformed, oversized, missing, future or stale observations. It has a fixed `pg_catalog,pg_temp` search path. Runtime roles receive only schema usage and execution of this argument-free function; they receive no server-file role, arbitrary path access or ability to replace the function. These choices follow PostgreSQL's [server-file privilege documentation](https://www.postgresql.org/docs/18/functions-admin.html#FUNCTIONS-ADMIN-GENFILE) and [security-definer guidance](https://www.postgresql.org/docs/18/sql-createfunction.html#SQL-CREATEFUNCTION-SECURITY).

Intake and dispatch require an observation no older than 15 seconds and at least the greater of 20% of filesystem capacity or 64 MiB available. Missing capability fails closed. Existing logical owner quotas remain in force. Accepted completion processing and recovery reads do not use this new-work admission gate. The diagnostic endpoint distinguishes `HEALTHY`, `CRITICAL`, `STALE` and `UNAVAILABLE`; insufficient capacity does not masquerade as an empty backlog.

The function and transient report are infrastructure state. Business checkpoints exclude `cutover_ops`; the administrator recreates it on the destination so restored software sees that destination's current filesystem, never old free-space evidence. The separate schema also lets the deliberately retained legacy business schema receive the same physical admission guard without changing its extraction boundary.

A disposable 384 MiB tmpfs test exercises actual allocated pages, refusal before reserve exhaustion, retained accepted state, completion updates and recovery after removing only its own filler file. Separate tests exercise probe expiry and runtime permission denial. These component checks do not by themselves establish the full deployed A26 scenario. The probe is an early admission guard, not protection against arbitrary host-wide disk consumption between observations or loss of the host.
